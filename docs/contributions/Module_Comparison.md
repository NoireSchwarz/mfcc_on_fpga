Updated 2026-11-20. Original: [Alex Schwalb Mel Filter Bank](https://github.com/lxschwalb/fpga_mel_filter_bank/tree/0148cd8f4927b6a125a5869b8aa16796e065ab27), commit `0148cd8`. Current RTL: SkewDCT branch, source revision `5ecd9f6`.

The comparison counts **12 major algorithm/processing blocks**, grouped into five processing stages. FFT16, FFT256, FFT2x, SkewDCT8 and DCT8 TDM set the transform-level granularity. Wrappers, memories, buffers, controllers, schedulers and normalization helpers are included in their parent block's implementation or remarks and are **not counted separately**. The optional MatrixDCT reference and retained legacy helpers remain in the source delivery but are excluded from this active-SkewDCT count.

**IP core** identifies a vendor-generated implementation in the original project. **Custom RTL** identifies visible project RTL, including integrated/adapted arithmetic and modified upstream stages. DSP and BRAM inference is allowed. This classification does not claim invention of established FFT/DCT algorithms.

## Scope and evidence

- The original project outputs 40 Mel features and has no DCT. The current SkewDCT branch adds a complete 64-point DCT and outputs all 64 cepstral coefficients.
- The original XFFT configuration is fixed at 512 points, with runtime length selection disabled. Our standalone FFT supports 16/32/64/128/256/512/1024/2048. The complete MFCC uses an elaboration-time `N`, rather than exposing the standalone FFT's runtime `size_sel` port.
- [S2: AMD PG109](https://docs.amd.com/r/en-US/pg109-xfft/Configuration-Tab) specifies a 64-point minimum for **Radix-4 Burst I/O**. Other XFFT architectures support 16/32 as well. The small-size restriction does not apply to the entire XFFT family.
- Mel weighting uses a sparse two-destination lookup and 64-bit energy accumulation. Log conversion uses floor clamping, leading-one/exponent processing, a 1024-entry Q20 mantissa table and Q8 output, following the project's `20*log10(energy)` convention. This is not by itself a recognition-accuracy claim.
- All 48 RTL files remain covered by [Source_Inventory.json](Source_Inventory.json). File-to-block mappings are implementation evidence, not additional counted modules. The original `src/ip/` directory is retained; packaged FFT/multiplier IP is not instantiated in the custom production datapath.
- The previously verified source ZIP is unchanged by this table revision. Its RTL matches the same source revision and retains the N1024 four-frame regression result: 256 coefficients, 39,508 testbench cycles, identical to the final-waveform regression.
