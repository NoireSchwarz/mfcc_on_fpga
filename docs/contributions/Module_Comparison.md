# Module comparison: original Mel Filter Bank and final SkewDCT branch

Updated 2026-11-20. The comparison uses the unmodified upstream [Alex Schwalb Mel Filter Bank repository](https://github.com/lxschwalb/fpga_mel_filter_bank/blob/0148cd8f4927b6a125a5869b8aa16796e065ab27/README.md), commit `0148cd8`, and our final SkewDCT RTL, source commit `5ecd9f6`.

[Excel table](Module_Comparison.xlsx) | [CSV table](Module_Comparison.csv) | [Structured table](Module_Comparison.json) | [RTL source inventory](Source_Inventory.csv) | [Final RTL source bundle](MFCC_SkewDCT_Final_Source.zip) | [Current source directory](../../src/work)

The table follows five processing stages. It contains **26 functional groups**, including one optional MatrixDCT comparison backend. Wrappers, major arithmetic cores and memory subsystems are grouped at architectural granularity. A functional group can span several files, or share a file with another group. These rows are not additive physical instance counts.

**IP core** explicitly identifies a vendor-generated implementation in the original project. **Custom RTL** identifies our visible RTL implementation or integration. It does not mean that the FFT/DCT mathematics or every reused arithmetic primitive was invented in this project. Modified upstream stages and integrated/adapted primitives are described accordingly. DSP and BRAM inference by synthesis remains allowed.

## Scope and implementation notes

- The original output is **40 Mel features**, not 13 MFCC coefficients. There is no DCT in the upstream top-level chain. Our active backend adds the complete 64-point DCT stage.
- The standalone custom FFT supports runtime selection of all eight lengths. The complete MFCC uses the elaboration-time `N` parameter; the current public MFCC interface does not expose a runtime `size_sel` port.
- [AMD PG109, Configuration Tab](https://docs.amd.com/r/en-US/pg109-xfft/Configuration-Tab) states that **Radix-4 Burst I/O** starts at 64 points. Pipelined Streaming, Radix-2 Burst and Radix-2 Lite also support 16/32. Small-size support must not be presented as a feature absent from the whole XFFT product family. The original packaged XFFT is fixed at 512 with runtime length disabled and automatic architecture selection.
- The active logarithm follows the project's `20*log10(energy)` convention. It uses an explicit floor, fractional mantissa lookup and tagged pipeline instead of the original integer dB case table. This is a numerical/architecture change; it is not by itself evidence of improved classification accuracy.
- `src/ip/` is retained for the original/vendor reference files. No packaged XFFT or multiplier IP is instantiated in the delivered `src/work` production datapath. FPGA DSP/BRAM primitives can still be inferred.
- The optional MatrixDCT backend and retained legacy/helper RTL are identified in the inventory. Their presence is not counted as additional active SkewDCT arithmetic.

All **48 RTL files** in `sim/rtl_sources.f` are accounted for in [Source_Inventory.json](Source_Inventory.json), with SHA-256 hashes, functional-group ownership and compatibility/reference roles.
